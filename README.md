# Time Vortex Boti Fix

Клиентский мод для Fabric 26.3, который заменяет старый `timevortex-bundlefix`.

## Зачем

В Time Vortex 1.3.11 автор уже сам исправил ошибку с bundle-пакетами (`SeamPacket.unbundle`),
поэтому старый bundlefix больше не нужен. Остался другой, графический баг: при открытии двери ТАРДИС
`FarSections.frame()` забирает **всю** очередь готовых секций внешнего мира и заливает их в видеобуфер
за один кадр, без ограничения. Отсюда огромный пролаг, а на слабой машине падение Java в
`StagingBuffer.tryAppend` (запись за границу буфера, EXCEPTION_ACCESS_VIOLATION).

Мод ограничивает загрузку по времени и количеству секций за кадр. Остаток ждёт следующих кадров.
Картинка через двери не отключается и не упрощается, она просто достраивается за несколько кадров.

## Сборка (через GitHub, как в прошлый раз)

1. Загрузи содержимое папки в репозиторий, проверь, что есть `.github/workflows/build.yml`.
2. Вкладка Actions → дождись зелёной галочки → скачай Artifacts.
3. Нужен файл `timevortex-botifix-1.1.0.jar` (без `-sources`).

Локально: JDK 25 и `gradlew build`, готовый jar в `build/libs/`.

## Установка

1. **Удали** из `mods` старый `timevortex-bundlefix-1.0.0.jar`.
2. Положи туда `timevortex-botifix-1.1.0.jar`.
3. После открытия дверей в `latest.log` появится строка (один раз за запуск):
   `[TimeVortexBotiFix] Spreading far-section uploads over several frames ...`

## Настройка (аргументы JVM, необязательно)

- `-Dtvbotifix.ms=2.5` время на кадр в миллисекундах (по умолчанию 2.5)
- `-Dtvbotifix.max=16` секций на кадр (по умолчанию 16)

Меньше значения: плавнее, но вид через дверь достраивается дольше.
Если после открытия двери в окне долго пусто, подними значения. Если всё ещё лагает, опусти.

## Если краши продолжатся

Пришли `hs_err_pid*.log` и `latest.log`. Мод проверен только на заглушках: настоящую сборку
против Minecraft 26.3 можно сделать только на твоём компьютере.
